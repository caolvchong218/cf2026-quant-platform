# 青序 v2.3.0：因子研发与策略验证

本版在现有研究工作台增加可解释的因子研发、年度训练、成交压力、收益归因和前向观察。原主线 `v3/rolling_lightgbm__managed` 继续保留；新增路线是可对照的辅助研究，不根据已经看过的历史收益自动替换主线。

本轮采用本地公式目录与真实 Tushare 快照。LLM 接口可切换服务，但本轮没有实际调用外部模型或本机 Ollama；`llm_called=false` 的含义按实验协议保留。以下成绩读取修正重名后发布的最终证据，原主线仍是保留路线。

## 1. 页面与使用顺序

| 入口 | 可以做什么 | 结果含义 |
| --- | --- | --- |
| 左侧“研究空间”→“回测实验” | 选择已有策略版本，查看或重跑原路线 | 原模型、日期、费用与股票池继续有独立身份 |
| “因子研发”→“公式与研究方案” | 看公式/假设、检查白名单表达式、保存方案、启动独立实验 | 公式合法不等于因子有效；每轮使用新的输出目录 |
| “因子研发”→“真实数据对照” | 切换2023–2024验证与2025起历史对照，查看候选/曲线/训练身份 | 最终历史成绩不能替代验证期预选 |
| “因子研发”→“持仓解释” | 看所选股票的形成日、因子贡献、实际期末权重 | 解释评分来源，不能证明因子造成收益 |
| “因子研发”→“模型辅助” | 用户选择服务、填写模型名称，再主动获取建议或解释 | 模型文本未核验；有效公式仍要进入新实验 |
| “策略验证” | 看成交约束、资金归因、前向计划和多策略组合 | 各自保留核账结果与证据边界 |
| “策略验证”→“指数增强” | 上传权重CSV、设置主动偏离/暴露、运行独立目标与成交账本 | 真实权重缺失时禁用运行；格式样例是虚构输入 |

缺少本地私有快照时，可读随包聚合证据；“运行真实数据研究”会禁用。“运行合成流程示例”只检查软件流程，不是投资效果证据。逐股订单、归因和持仓解释需要本地完整实验明细。

## 2. 有限因子目录与安全表达式

默认目录含 **28个不同因子ID：12个既有经济因子＋16个 `dsl_` 命名空间公式**。命名空间避免同名覆盖；28个ID不代表28个相互独立的信息源，冗余仍由训练期筛查识别。

既有因子是 `momentum_60_20`、`reversal_5`、`low_volatility_20`、`range_20`、`trend_20`、`volume_trend`、`liquidity_20`、`turnover`、`earnings_yield`、`book_yield`、`dividend_yield`、`quality_roe`，定义沿用 [V2因子卡](FACTOR_CARDS_V2.md)。DSL目录包含20/60日动量、反转、均价偏离、低波动、波动变化、振幅、相对成交量、成交量趋势、实体压力、收盘位置、价量相关、趋势量能、波动调整趋势、距历史高点和低点。

DSL只解释经过AST检查的表达式，不执行任意Python。输入为日期×资产的 `open/high/low/close/volume`；支持历史滞后、收益率、滚动统计、同日横截面rank/zscore等白名单算子。它禁止负向历史窗口、未知字段及任意属性/函数执行。公式使用当日收盘信息时，信号在收盘之后形成，成交仍需下一开盘。

既有因子读取已核对身份的 `n_` 特征。新增DSL按形成日截尾、标准化，再按当时行业与对数市值中性化；缺失保留，不用未来数据回填。财报和历史行业规则沿用原流程。因子中性化不保证实际股票组合行业、市值或beta完全中性。

实现与目录依据：[factor_lab.py](../src/cfquant/factor_lab.py)、[research_lab.py](../src/cfquant/research_lab.py)、[features.py](../src/cfquant/features.py)。

## 3. 时间划分、筛选与年度训练

| 阶段 | 用途 | 允许据此决定什么 |
| --- | --- | --- |
| 初始训练主体2020–2022 | 冻结最多6个因子ID，估计方向/强度并排除冗余 | 因子身份；不使用2023以后收益筛因子 |
| 2023–2024验证 | 比较三个辅助候选，按夏普降序、ID解同分写出预选 | 辅助路线预选；先写selection再进入后续历史比较 |
| 2025-01-02至快照末日（当前2026-09-18） | 与保留主线及固定融合做历史开发对照 | 如实报告效果；不能重新称为未见盲测 |
| 冻结计划后的新交易日 | 追加本地观察与来源记录 | 积累前向材料；当前不构成真实前向或实盘证明 |

实际训练边界由形成日 `cutoff` 决定：`cutoff - 3年 <= date < cutoff`，且20交易日标签退出日 `label_exit < cutoff`。初始形成日是2023首个交易日前一交易日；精确边界可能含2019年末的少量预热日期，应以 `protocol.json` 和 `folds.json` 为准，不把日历年概述当成精确筛选条件。

标签为形成日后下一开盘买入、再20交易日后开盘退出的复权收益。Ridge训练目标是同日横截面标签排名减0.5，不是收益率数值预测。2023–2026每年更新一次模型，只用形成日前最近三年且已经实现的标签；选中的因子ID保持冻结，方向与Ridge系数可以按年度训练重新估计。

默认最多筛6个因子，要求训练标签覆盖至少80%、有效日至少60日；按绝对平均Rank IC排序，对已选因子的绝对相关性超过0.75时排除。完整筛选记录包含淘汰理由，不只展示成功因子。

本轮冻结的6个ID为 `turnover`、`low_volatility_20`、`dsl_momentum_60`、`dsl_price_volume_corr`、`dsl_momentum_20`、`book_yield`；验证期预选为 `mined_ridge`。依据：[decision.json](../evidence/research_v4/decision.json)、[screening.csv](../evidence/research_v4/screening.csv)。

## 4. 比较路线与持仓解释

| 候选ID | 计算与用途 |
| --- | --- |
| `mainline` | 使用原年度LightGBM分数，以相同组合/成交条件重算对照 |
| `fixed_whitebox` | 盈利收益率、账面市值比、股息率、ROE、低波动、低振幅六因子，横截面排名减0.5后等权 |
| `mined_rank` | 冻结所选因子ID，年度训练估计方向，完整因子观测的排名等权组合 |
| `mined_ridge` | 同一所选因子集，年度Ridge `alpha=100`，记录系数与截距 |
| `blend` | 主线与 `mined_rank` 的目标权重各50%，合并后重新进入同一成交引擎 |

融合权重预先固定，不在已观察的最终区间反复搜索。它不是两条净值曲线的简单平均；重叠持仓、现金、订单受阻与费用会影响真实账本。

默认组合每20交易日调仓，目标50股、20名缓冲、逆波动权重、单股目标4%、行业目标25%、总仓位最高95%、20%波动预算和120日趋势条件。上限约束留下现金，实际持仓权重随价格和受阻成交漂移。

持仓解释读取形成日排名值、固定权重或年度系数；Ridge同时保留截距。期末实际持仓来自账本，贡献表说明评分计算，不把模型文字当作因果归因。

| 路线 | 累计净收益 | 年化收益 | 夏普 | 最大回撤 | 对沪深300全收益指数的收益差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定经济白箱 | 13.90% | 8.18% | 0.673 | 14.74% | -6.04个百分点 |
| 筛选排名白箱 | 15.63% | 9.17% | 0.657 | 15.08% | -4.31个百分点 |

## 5. 成交压力和资金归因

原基线沿用买10bp/卖15bp，并限制成交额为前20交易日均值的1%。严格情景加入100股原始等价整手、最低佣金、显式配置的印花税、滑点现金成本、T+1可卖检查和同一滞后流动性预算；政策写入 `policy.json`，独立核对写入 `checks.json`。税费是本次明确的研究情景，不是按政策名称推断的完整交易规则。

**严格执行仍以连续复权单位记账，整手限制通过成交日 `adjusted_open/raw_open` 换算为原始等价股数。** 它没有完整模拟分红现金、企业行动、托管余额和清算，不应称作完整交易所模拟器。严格情景费率与原基线不同，差异不能全部归因于整手；双倍基线费用另列对照。

逐股资金损益为：卖出现金流−买入现金流−实际成本＋期末持仓价值。逐股贡献相加核对组合净收益，行业归因按明确提供的期末历史行业标签汇总，是描述性的资金账本分组，不是因子因果贡献。相同实际成交的 `gross_attribution_nav` 只是补回已付成本；真正免手续费反事实必须重新执行。

依据：[execution_constraints.py](../src/cfquant/execution_constraints.py)、[return_attribution.py](../src/cfquant/return_attribution.py)。

## 6. 指数增强输入：就绪，真实历史结果待完成

指数增强模块接受真实历史权重CSV，必需列为 `date,asset,weight,known_at`。`weight`默认是0–1比例；百分数输入必须显式转换。每个完整快照权重之和必须为1，日期/资产不得重复，代码导入时保留前导零，发布时点与形成时点使用同一时钟。

构建目标只允许使用形成时点之前已经完整可见的权重快照，不从未来成分倒推历史。全部成分需要存在于价格面板，缺行情/行业等必要输入时记录阻止原因并保持目标NaN，不静默重归一化为子集指数，也不把阻止状态展示成成功现金组合。个股和行业主动偏离相对于同股票敞口缩放后的基准，目标还受总敞口限制。

**本次真实历史指数成分权重缺失。CSV输入与目标构建接口已经准备，未形成真实数据指数增强实测结果。** 现有价格指数、全收益指数或ETF序列可以作收益比较，不能充当历史成分权重。输入有效、目标约束通过、成交账本通过、跑赢基准是不同状态，需分别记录。

页面操作为：“策略验证”→“指数增强”→“上传历史指数权重 CSV”。百分数文件勾选“上传文件 weight 使用百分数（显式除以100）”；选择“指数增强使用的 V4 分数”，设置“个股主动偏离上限”“行业主动偏离上限”“权益目标暴露”、起止日和调仓间隔，再点“运行并保存指数增强回测”。缺权重或本地快照/分数时按钮禁用；“下载格式样例（虚构权重）”只说明格式，不是沪深300数据。

成功运行会独立保存配置诊断、目标权重、四张成交账本、指标、资金归因和输入/输出/源码身份。当前页面收益对照使用本地沪深300价格序列；上传权重的指数身份由用户提供，软件不会认证来源。上传其他指数不能把这一比较自动当作对应指数基准。

依据：[index_enhancement.py](../src/cfquant/index_enhancement.py)。

## 7. LLM：由用户选模型后主动运行

在“因子研发”→“模型辅助”选择“模型连接”，填写所用模型名称、服务地址和所需密钥，再点“获取研究建议”或“解释当前所选持仓”。兼容接口和Ollama未填模型名时按钮禁用；选择服务不会自动发请求。

支持 `offline`、OpenAI Chat Completions兼容接口、Ollama。离线回答标为“离线确定性解释（未调用模型）”，服务模型回答标为“模型解释（未核验文本）”。服务与模型名、提示版本、可复核指标、建议公式来源一并记录；密钥不写入方案或发布材料。

模型只承担研究建议和解释，不直接产生成交指令，不替代数值评价器。提出的公式需通过同一个DSL检查；“将有效建议保存为研究方案”只保存待验证方案。随后在“公式与研究方案”勾选“加入已保存的自定义公式”并启动新的独立实验，才会有实测结论。本轮交付不声称已有真实模型生成或改进收益的证据。

依据：[llm_research.py](../src/cfquant/llm_research.py)、[ui_factor_lab.py](../src/cfquant/ui_factor_lab.py)。

## 8. 前向观察的可核验状态

“策略验证”→“前向观察”先选“待观察策略”，点“冻结新的观察计划”。冻结文件记录策略、配置、源码和数据身份及哈希、截止日、冻结时刻；后续记录只追加，校验链与顺序。下载计划可保存当时定义。

状态区分 `awaiting_new_sessions`、`historical_post_freeze_replay`、`forward_paper_observations`。截止日之后但冻结当日或更早已经发生的历史，仍属于历史复核。手工录入仅是本地纸面观察，时间戳来自本地或调用方，不能证明当时的信息可得性和成交真实性；当前 `genuine_forward_verified=false` 必须保留。方案冻结和记录校验通过不等于取得真正前向验证结论。

依据：[forward_observer.py](../src/cfquant/forward_observer.py)。

## 9. 复现与证据索引

已安装项目依赖的Python环境中，从项目根目录运行；给每次实验一个不存在的新输出目录：

```powershell
python scripts/run_factor_research.py --data-root <已有原快照项目根目录> --output runs/<新的实验ID>
```

发布真实聚合证据时可加 `--publish`；已有发布目录会拒绝覆盖。`--demo`仅为合成流程，并且不能替换真实发布证据。公开证据包含聚合表、逐日账本和身份；逐股行情、分数与成交明细留在本地完整实验。

## 10. 参考与复用边界

[Qlib官方仓库](https://github.com/microsoft/qlib)提供数据、模型训练、回测评价及模块化研究流程；本版沿用已有Qlib接入，并在现有成交核心外增加独立辅助路线。[RD-Agent官方仓库](https://github.com/microsoft/RD-Agent)提供提出假设、实施实验、用反馈迭代的研发思路。本版借鉴该流程，没有运行其完整自主因子/模型联合优化，也没有把官方示例收益移植为本项目成绩。

本地CogAlpha 1.4.1包的核心哈希与1.4.0一致，版本增量主要是启动修复。具体审阅与采用范围见 [COGALPHA_141_REVIEW.md](COGALPHA_141_REVIEW.md)；补充演示见 [DEMO_SCRIPT_V230.md](DEMO_SCRIPT_V230.md)。
