# 大面板数值重复性审计

2026-09-21，重复运行时发现一个主实验意外全持现金，风险估计波动率约为0，其他候选及同分数的费用对照却正常。该异常运行被归档，不能作为可验收策略结果。

## 复现证据

逐步将完整研究缩减为大DataFrame的`pct_change(fill_method=None)`与NumPy逐项除法对照。随机种子7，1690×1000正数矩阵，重复分配并交替C/F布局，在本机Python3.13/Anaconda、pandas2.3.3、NumPy2.3.5、NumExpr2.14.1环境复现：

```
FAIL 6 strides (8000, 8) no_numexpr_matches True actualminmax 0.0 0.0
```

同一输入关闭`compute.use_numexpr`后与独立除法一致。预先加入的`tests/test_numerics.py`也在修复前失败，得到全部−1且NaN位置不一致；修复后通过。这个证据定位到本机可选表达式加速路径，不等于已经证明所有平台的该版本都存在相同上游缺陷。

## 修复与重算

`cfquant.__init__`统一禁用pandas可选NumExpr加速，使用NumPy参考路径。该设置对当前Python进程生效，已在复现指南披露。特征缓存身份包含该数值策略文件，策略改变时强制重建。原始行情无需重新下载。

重新生成因子、模型、风险权重、回测、对照、诊断和最终材料，保留修复前运行。重新复算的原始动量累计收益−83.5698%、零费用重跑−75.1586%，与此前正确运行相同；异常没有解释掉原始策略的亏损。最终重复性、测试和数据核验结果以`evidence/research_v2`中的验收文件为准。

## 防止复发

回归测试覆盖超过可选加速阈值的大面板，并与独立公式逐元素核对；小型会计测试无法单独捕捉这一类错误。因此还需完整真实快照的重复运行，以及标准隔离环境下的验证。13个账本通过只能证明给定输入下的会计一致，不能代替上游特征的数值正确性。
