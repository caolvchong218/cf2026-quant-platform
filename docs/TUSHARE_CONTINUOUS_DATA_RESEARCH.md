# 青序持续数据更新：官方接口核查与实现契约

核查日期：2026-10-20。本文区分官方说明、本机只读核验和本项目设计选择。没有购买接口权限，没有发送委托；原始供应商数据、凭据、模型仍只保存在私有运行目录。

## 结论

继续使用现有 HTTPS `TushareProvider`，增加持久化日分区、公告驱动的财务刷新、可恢复的轮询队列以及有观察时间的行业版本。保持原 1,000 只股票池，不因新上市或当前存续状态悄悄更换研究样本。

本账号可以走普通财务接口和披露日期接口，不依赖 VIP。接口支持的范围不足以证明“取得了所有历史修订版本”；已有历史训练数据保留原身份，新的前向观测从实际取得时间开始生效。后来的供应商修订不能改变已冻结的历史特征、信号或委托。

## 已有实现的复用选择

| 官方实现 | 核查所得 | 采用方式 |
|---|---|---|
| [Tushare Python 客户端](https://github.com/waditu/tushare/blob/master/tushare/pro/client.py) | `DataApi.query` 封装 API 名、字段及参数并返回 DataFrame，没有持久化增量队列、自动分页或财务时点数据库 | 保留本项目已有 HTTPS、凭据隔离、限流和响应缓存；不另换一个功能相近的客户端 |
| [Qlib PIT 数据库](https://qlib.readthedocs.io/en/latest/advanced/PIT.html) | 明确区分报告期与公布日，允许同一报告期出现多个修订值 | 借鉴版本保留及按历史时点选择；本地额外记录 `first_seen_at`，防止供应商回填旧日期 |
| [Qlib PIT collector](https://github.com/microsoft/qlib/blob/main/scripts/data_collector/pit/README.md) | 现有采集器使用 Baostock；公布日缺失时有固定日历天偏移兜底，官方提示数据可能不完整 | 不替换现有 Tushare 数据源，也不以固定偏移伪造财报公布日；后续可将已核验数据导出 Qlib PIT 格式 |
| [Qlib Yahoo 增量采集](https://github.com/microsoft/qlib/blob/main/scripts/data_collector/yahoo/collector.py) | `update_data_to_bin` 从本地日历末端扩展、规范化，再调用 `DumpDataUpdate` | 借鉴增量边界和本地状态复用；青序另外加入分区完整性、观察版本及中断恢复 |

2026-10-20 直接核查 Qlib 主干 `scripts/data_collector/tushare/collector.py` 路径返回 404。因此不能把搜索到的未确认 PR/工作流当作已合并、可直接部署的成熟 Tushare 采集器。本项目适配上述成熟模式，而非声称已复用了不存在于该路径的程序。

## 财务接口与历史时点

[财务指标官方文档](https://tushare.pro/document/2?doc_id=79)规定普通 `fina_indicator` 按单只股票查询，每次最多 100 行；`start_date/end_date` 是**报告期**范围，`ann_date` 是公告日，`period` 是季度末。返回字段含 `ann_date/end_date/roe/update_flag`，没有列出 `f_ann_date`。全市场季度接口 `fina_indicator_vip` 另需相应权限。

本机核验：查询 `20250101–20251231` 报告期确实返回公告日延伸至 2026-03-31 的记录。因此不能使用“上次抓取日期”作为该接口的报告期起点，否则会漏掉较早报告期刚发布或修订的数据。

[利润表文档](https://tushare.pro/document/2?doc_id=33)的 `income` 则提供 `f_ann_date`，其开始/结束日期描述为公告日期范围。不同接口同名参数不保证相同含义。[现金流量表文档](https://tushare.pro/document/2?doc_id=44)还区分最新、调整后及调整前报表类型。`update_flag=1` 表示当前更新版本，不能据此认定该数值在过去已经可知。

项目选择：

- 质量因子继续使用年度 ROE，不以季度 ROE 替换原策略定义。
- 对已经存在可用前向观测的股票，新路线先选最大可用报告年度，再处理该年度的公布身份及修订；晚发布的旧年度重述不能覆盖已知的更新年度年报。同一身份冲突仍按缺失处理。只有继承参考数据、尚无可用新观测的历史形成日继续原有选择规则，不重写已验收的旧特征。
- 对取得的年度指标保留原公告日。`income` 只在报告期与公告身份可明确匹配时辅助确定更晚的实际公布日；有歧义时延后或标记缺失，不把另一份报表日期强行接到该 ROE 上。
- 同一财报身份但值冲突时不按收益结果挑选；保存观察版本、记录冲突，并按保守规则处理。
- 新修订的可用时点至少同时满足公布日门限与首次观察门限。今天首次取得、却标有去年的公告日的修订不能被写入去年的特征。
- 原有历史快照属于历史继承数据。记录的本次导入时间不证明其所有原始修订在历史上已经可得；不能把整个训练集宣传成完整的历史版本数据库。

[披露日期接口](https://tushare.pro/document/2?doc_id=162)支持不传股票代码、按 `actual_date` 查询，最多 6,000 行；输出还含计划日和披露日期修改记录。其用途是触发刷新，计划披露日不是财务数值已经可用的证据。本机 `actual_date=20261020` 返回 57 条。每天处理遗漏的公告日，并将涉及原股票池的股票加入财务队列；每月另外轮询整个固定池，捕获非首次披露的修订。每股查询近几个报告年度，超过 100 行时继续拆报告期，不接受静默截断。该轮询制度能发现修订，但不承诺供应商提供完整修订历史或每次修订均在当日被发现。

## 行业、上市与退市

[申万分级成分接口](https://tushare.pro/document/2?doc_id=335)支持按 L1/L2/L3 或股票查询，`is_new` 默认 Y，提供 `in_date/out_date`，单次最多 2,000 条；没有公布“修改时间增量游标”。[行业分类接口](https://tushare.pro/document/2?doc_id=181)明确区分 SW2014 与 SW2021。

项目固定 SW2021，按 31 个一级行业分批抓取 Y/N，响应达到上限时拆分更细行业或固定池股票。保存每次已完成的行业观察集合，比较版本；不能把今天补齐的历史行业间隙直接写回过去。原有 `in_date <= date < out_date` 是本项目区间约定；官方文档未严格定义退出日包含性，发生行业重叠仍保留 UNKNOWN。

[股票基础信息](https://tushare.pro/document/2?doc_id=25)提供上市状态、上市日、退市日，默认仅 L；还可查询 D/P 等状态。文档上限 6,000 行，每分钟 50 次。应按交易所与状态抓取并保存观察快照，不能用当前 L 列表重写原历史股票池。退市或暂停状态可以阻止新买入，但不能抹掉实际持仓和待核验成交。缺一天行情也不等于已经退市。[按日历史列表 `bak_basic`](https://tushare.pro/document/2?doc_id=262)是另一个接口，本账号此次未通过，因此不依赖它。

## 行情、分页与调度

| 接口 | 官方约束及持续更新处理 |
|---|---|
| [daily](https://tushare.pro/document/2?doc_id=27) | 非复权日线，停牌日没有记录，单次 6,000 行；支持单日和逗号分隔股票查询。按交易日存储，不能把缺行当作零收益 |
| [daily_basic](https://tushare.pro/document/2?doc_id=32) | 单次 6,000 行，通常交易日 15–17 时更新；行情收盘不代表基本面日指标已完整入库 |
| [adj_factor](https://tushare.pro/document/2?doc_id=28) | 支持单股历史或单日全市场；保留原始价及当日因子，复权基准必须和原训练口径一致 |
| [stk_limit](https://tushare.pro/document/2?doc_id=183) | 文档单次上限 5,800，范围包括 A/B 股和基金。不能用全市场请求的行数与固定 1,000 池行数混淆完整性 |

官方通用[权限/频率表](https://tushare.pro/document/1?doc_id=290)按账号等级分档，个别接口另有限制。本机没有读取账户积分，也不据一次成功响应推断无限权限。现有 1.3 秒请求间隔约每分钟 46 次，可作为保守默认；多线程须共享限流器。权限错误不无限重试；网络错误有有限退避并保留成功检查点。

官方客户端只是转发 `limit/offset` 等参数，不表示每个端点都提供同样分页保证。本机仅验证 `stock_basic` 两个 `limit=2, offset=0/2` 页面均成功且不重叠。其他端点先按官方筛选维度拆分；触顶、重复页或无法证明结束时标记未完整，不用猜测补齐。

项目调度选择：日历决定待补交易日，持久化任务队列分批完成，因此不设置“超过 40 日永久拒绝”的总上限；每次运行仍有请求预算。关闭电脑或断网后可以续接。只有当前形成日所有必要分区及参考数据状态满足要求，才发布可执行信号。补齐旧行情不代表可事后补发旧委托。

## 建议数据契约

| 数据 | 最小字段或约束 |
|---|---|
| 固定池 | 原股票代码集合及 hash；上市状态作为有观察日期的独立过滤信息 |
| 市场日分区 | `trade_date/asset` 唯一；四个来源的请求身份、行数、完整性、取得时间、内容 hash |
| 财务版本 | `asset/report_period/ann_date/f_ann_date`（适用时）、值、源接口、`first_seen_at/revision_hash`；保留更早版本 |
| 行业版本 | 分类版本、成员区间、取得时间、完整分组身份；UNKNOWN 与未完成刷新显式区分 |
| 更新任务 | 类型、股票/行业/公告日、进度、重试状态、最后成功时间；重启不重复已完成任务 |
| 形成日快照 | `signal_date`、决策时点、源版本 IDs/hash、未处理任务数、参考新鲜度、局限说明 |

`ReferenceStore.snapshot_asof(signal_date)` 只服务这个指定形成日。它返回在该日门限以前已观察的参考版本；不能将这张当前表拿去重算更早的特征。原基线之后逐日冻结特征。跨年训练以已冻结特征和真实已完成的未来标签为输入，继续保留年界 cutoff、`label_exit < cutoff`、训练数据 hash 及固定参数，不能仅去掉“限 2026 年”的判断便声称跨年训练完整。

实现接口为 `ReferenceStore(root, base_financials, base_industries, assets, baseline_date)`；`refresh(provider, signal_date, observed_at=None, max_requests=24, observation_clock=None)` 保留成功检查点并返回 `completed_this_run`。生产默认在每次请求结束后读取真实时间；固定 `observed_at` 或可注入时钟用于测试。

`ready/maintenance_ready` 表示截至当前运行时间的采集维护已完成，`snapshot_full_scan_complete` 表示该形成日能否使用当期全部观察版本，两者有意分开。次日早上补跑前一晚时，维护可以完成，但只能使用昨天已知的旧版本；`uses_prior_reference_versions` 与 `reference_note` 会明确提示。财务公告仍严格早于形成日，当日收盘后已取得的旧公告修订可以用于当日生成的下一交易日信号。未来日期的财报记录会被忽略，须公布后重新取得，不能随着时间推移自动变成可用数据。

缓存需区分“同一个可恢复抓取任务”和“新的刷新任务”：前者复用响应，后者必须重新访问接口才能发现修订。旧版 `TushareProvider` 对相同 API/参数/字段永久复用同路径缓存，因此新任务应使用独立缓存命名空间；不能把永久缓存命中当作今日刷新成功。
